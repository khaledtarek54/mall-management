# Atriom Mobile API — v1

Mobile-facing REST API for the tenant app. All endpoints live under `/api/v1/`.

## Architecture

- **Single codebase, layered separation.** The API lives inside the same Laravel project as the Filament web panels (admin/portal/owner). API code is partitioned under `app/Http/Controllers/Api/V1/`, `app/Http/Requests/Api/V1/`, `app/Http/Resources/Api/V1/`, `app/Actions/Api/`. Nothing in those namespaces is reachable from the web panels and vice-versa.
- **Authentication.** Sanctum personal access tokens, bound to the `Tenant` model (not `User`). Tokens are device-bound — see `device_name` in the login payload.
- **Guard.** `tenant-api` (driver: `sanctum`, provider: `tenants`). Configured in [config/auth.php](../../config/auth.php).
- **Business logic.** Lives in single-action classes under `app/Actions/Api/{Domain}/{Verb}Action.php`. Controllers are thin: receive a `FormRequest`, call the action, return an API `Resource`.

## Conventions

### Request

- All endpoints accept JSON. Send `Accept: application/json` and `Content-Type: application/json`.
- Authenticated endpoints require `Authorization: Bearer {token}`.

### Response envelope

**Success (2xx)**
```json
{
  "data": { ... },
  "message": "Human-readable success message"
}
```

**Validation error (422)**
```json
{
  "message": "The given data was invalid.",
  "errors": {
    "email": ["These credentials do not match our records."]
  }
}
```

**Auth error (401)**
```json
{
  "message": "Unauthenticated."
}
```

**Throttled (429)**
```json
{
  "message": "Too Many Attempts."
}
```

### Locale

- The API respects the `Accept-Language` header (`en` or `ar`). All `message` fields are localized.

## Endpoints

### `POST /api/v1/auth/login`

Authenticate a tenant and issue a Sanctum access token. **No registration endpoint exists** — tenants are created by property admins via the Filament web panel.

**Throttle**: 5 attempts per minute per IP.

**Request**
```http
POST /api/v1/auth/login
Content-Type: application/json
Accept: application/json

{
  "email": "tenant1@haya.test",
  "password": "secret-pw",
  "device_name": "Khaled's iPhone 16 Pro"
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `email` | string | yes | Lowercased + trimmed server-side |
| `password` | string | yes | Plain text over TLS |
| `device_name` | string | yes | 1–100 chars. Labels the token for the user's "manage devices" screen. Logging in twice from the same `device_name` revokes the prior token. |

**Response — 200**
```json
{
  "data": {
    "tenant": {
      "id": 1,
      "name": "Café Crema",
      "legal_name": "Café Crema LLC",
      "type": "company",
      "email": "tenant1@haya.test",
      "phone": "+201441482265",
      "whatsapp": "+201750512166",
      "contact_person": "Ahmed Hassan",
      "status": "active",
      "tax_id": "430153706"
    },
    "token": "1|mAt7sfdIY7AQwU2Z7wJVLqUQ6dtCKYSEiyK6JGNY79b7d139",
    "token_type": "Bearer"
  },
  "message": "Signed in."
}
```

**Errors**
- `422` — invalid credentials, unknown email, blacklisted/inactive account, or missing/malformed fields. Error key is always `email`.
- `429` — throttle limit hit.

**Client storage**
- The `token` is a one-time secret. Store it in the device's secure store (Keychain/Keystore). Never log it.

### `GET /api/v1/auth/me`

Returns the currently authenticated tenant profile. Useful after app resume to refresh the cached profile.

**Request**
```http
GET /api/v1/auth/me
Authorization: Bearer 1|mAt7sfdIY7AQwU2Z7wJVLqUQ6dtCKYSEiyK6JGNY79b7d139
Accept: application/json
```

**Response — 200**
```json
{
  "data": {
    "id": 1,
    "name": "Café Crema",
    ...
  }
}
```

**Errors**
- `401` — missing, invalid, or revoked token.

---

### `POST /api/v1/auth/logout`

Revoke the access token used for the current request. Other devices keep working — for "log out everywhere", a separate `/auth/logout/all` endpoint will be added when needed.

**Request**
```http
POST /api/v1/auth/logout
Authorization: Bearer 1|mAt7sfdIY7AQwU2Z7wJVLqUQ6dtCKYSEiyK6JGNY79b7d139
Accept: application/json
```

**Response — 200**
```json
{ "message": "Signed out." }
```

After this, the same token returns `401` on every subsequent request.

## Adding new endpoints

Follow the same pattern as `LoginController`:

1. Define the route in `routes/api.php` inside the appropriate `auth:tenant-api` block.
2. Create a `FormRequest` under `app/Http/Requests/Api/V1/{Domain}/{VerbResourceRequest}.php` for validation.
3. Create an action under `app/Actions/Api/{Domain}/{VerbNounAction}.php`. One public `handle()` method. Throw `ValidationException` for failures.
4. Create a thin controller under `app/Http/Controllers/Api/V1/{Domain}/{Verb}Controller.php` that wires Request → Action → Resource.
5. Create an API Resource under `app/Http/Resources/Api/V1/{ModelResource}.php` to shape the response.
6. Add feature tests under `tests/Feature/Api/V1/{Domain}/`.
7. Document the endpoint in this file.

## Roadmap

- `GET /api/v1/invoices` — list tenant's invoices (paginated)
- `GET /api/v1/invoices/{id}` — invoice detail
- `GET /api/v1/invoices/{id}/pdf` — download invoice PDF
- `POST /api/v1/invoices/{id}/pay` — initiate Paymob payment (once credentials land)
- `GET /api/v1/me/requests` — list own requests
- `POST /api/v1/me/requests` — submit new request (+ photo uploads)
- `POST /api/v1/tenant-sales-declarations` — submit monthly sales
